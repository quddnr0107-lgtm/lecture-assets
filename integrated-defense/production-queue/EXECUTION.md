# 통합방위법 도식 큐 실행 기준

## 목표와 기준 자료

선택 완료된 **07 Notion 참고 흑백 편집형**으로 통합방위법 강의 도식을 보완하고, 실제 강의에서 읽을 수 있는 모바일 세로형을 완성한다. 기준은 `integrated-defense/notion-v1/`의 최신 content·manifest·style-guide와 이 폴더의 queue·coverage다.

기존 핵심 도식 49개는 완료된 기준 자산이다. 신규 내용 보완, 같은 내용의 모바일 변형, 검수 작업을 서로 다른 종류로 집계한다. 모바일 파일을 고유 법 내용 도식으로 중복 계산하지 않는다.

## 작업 배정

1. 매 실행 GitHub 기본 브랜치와 최신 `queue.json`을 읽는다. 로컬 사본보다 저장소 기록을 우선한다.
2. `depends_on`이 전부 완료된 `queued` 작업을 우선순위 순서로 선택한다. 가용 동시 작업 슬롯을 최대로 사용한다. 최초 환경은 조정 담당 1개와 작업 담당 3개, 총 4개 슬롯이었다. 실제 환경 한도를 넘는 가동 수를 주장하지 않는다.
3. 작업 시작 전에 해당 ID를 `running`으로 바꾸고 실행 ID·시작 시각·만료 시각을 lease에 기록한다. 다른 실행의 유효한 lease를 가져오지 않는다. 만료되면 실제 완료 파일과 기존 실행 상태를 확인한 후 복구한다.
4. 독립 작업은 병렬 처리하고 완료 즉시 다음 준비된 작업을 배정한다. 한 번의 실행을 단순 상태 조회로 끝내지 말고 가능한 실제 제작·검수를 진행한다.
5. 작업자는 강의별·작업 ID별 파일을 담당한다. 공용 content·manifest·gallery·queue와 브랜치 반영은 조정 담당이 취합한다.

## 제작과 검증

- 신규 보완 도식은 law.go.kr의 최신 해당 조문을 직접 확인하고 법률·시행령, 공포일·시행일·확인일을 구분한다. 기존 법정 기준일과 다른 시행예정 내용을 임의로 섞지 않는다.
- 정확한 한글과 관계가 필요한 도식은 SVG 등 결정적으로 편집 가능한 원본으로 제작한다. 이미지 생성 모델에 법 문구를 맡기지 않는다.
- 기존 제작 스크립트와 스타일을 재사용한다. 새 개수를 지원하도록 49개 고정 검증값은 실제 데이터 개수와 대응하는 검사로 변경한다.
- 모바일은 폭 1080px를 기본으로 하고, 390px 표시 폭에서 핵심 본문이 14px 이상에 해당하도록 만든다. 긴 문장은 의미 단위로 재배치하고 필요하면 페이지를 나눈다. 단순 축소본으로 완료 처리하지 않는다.
- 주체·요건·의무·재량·예외·근거를 보존한다. 비교·구성을 절차 화살표로 잘못 표시하지 않는다.
- SVG·PNG·WebP를 렌더링하고 실제 이미지에서 한글·잘림·겹침·여백·작은 화면의 가독성을 확인한다. 원문과 출력 텍스트, 파일 크기·SHA-256, 강의별 링크도 검사한다.
- 새 번호는 해당 강의의 미사용 D번호를 배정한다. 모바일은 원본 ID와 페이지 번호를 연결하여 `lesson-NNN/diagrams/notion-v1/mobile/`에 저장한다.
- 비공개 강의 낭독 원문, 영상·음성 파일, 서명 URL, 비밀값을 공개 저장소에 넣지 않는다. 공개할 내용은 학습용 법령 요약과 자산·검수 정보다.

## 저장소 반영

`quddnr0107-lgtm/lecture-assets`의 과목·강의별 폴더에 저장한다. 다른 과목·사진 작업도 같은 저장소를 사용하므로 커밋 직전의 최신 HEAD와 트리를 읽어 병합하고, 기존 파일을 보존하며 expected SHA로 참조를 갱신한다. 충돌하면 최신 내용을 다시 읽어 반영하고 강제 갱신하지 않는다.

완료는 실제 결과 파일과 출처·검수·manifest가 저장되고 원격 파일까지 확인된 경우만 기록한다. 실행 기록은 `runs/`에 변경 ID, 결과 파일, 검수 결과, 커밋을 남긴다. 임시 오류·접근 실패를 완료나 변경 없음으로 처리하지 않는다. 한 작업이 막혀도 다른 독립 작업을 계속 처리한다.

이 큐의 범위는 통합방위법 도식 자산이다. 다른 과목의 별도 큐와 겹쳐 제작하지 않는다. 강의 영상 편집, 자막 타이밍 확정, 운영 사이트 배포는 이 큐의 완료 조건에 포함하지 않는다.

## 보고와 종료

모든 30개 초기 작업과 실행 중 필요에 따라 추가된 실제 후속 작업의 검수가 끝나면 최종 목록·다운로드 묶음을 정리한다. 최종 완료를 보고하고 이 통합방위법 전용 예약만 비활성화한다.
