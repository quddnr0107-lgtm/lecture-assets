# 훈령 도식: 제80회 기존 스크립트로 실행

[작업 큐](production-queue.json) · [스크립트 기준](SCRIPT-BASIS.md) · [78편 경로·해시](script-basis.json) · [전체 도식](../diagrams-manifest.json)

## 확정된 내용 기준

사용자의 2026-11-27 정정에 따라 **제80회(2027년 전반기)의 기존 강의 스크립트**를 그대로 시각화한다. 내용·설명 순서·수치·조건·예외·강의 번호는 기존 스크립트가 우선이다. 공식 법령은 인용 확인에 사용하는 보조 근거이며 오늘의 현행판을 별도 원고로 재구성하지 않는다.

기존 통합 스크립트는 `script-basis.json`에 강의별 경로·Git blob·SHA-256을 기록했다. 실제 원고는 연결된 원본 저장소에서 읽는다. 원고 파일을 다른 과목·구버전으로 대체하지 않고 원본 원고·음성·영상은 수정하지 않는다. 원고 접근이 막히면 해당 작업의 구체적인 차단 사유를 기록한다.

기준 실적은 **78강·190장 / SVG·PNG·WebP 570개 파일 제작**이다. 파일이 있다는 사실과 제80회 스크립트 전체 대조 완료를 구분한다. 큐의 78건은 기존 스크립트와의 일치·필요한 도식 보강 검토다. 새 장수 목표를 임의로 정하지 않는다.

## 최대 병렬 처리

실제 허용되는 동시 작업 수를 최대한 사용한다. 설정 당시에는 총 4슬롯이므로 조정자 1명과 작업자 3명이다. 환경 한도가 달라지면 그에 맞추고 한 슬롯만 있으면 순차로 처리한다. 가용 시간·토큰·도구 한도 안에서 할 일이 남으면 작업자에게 다음 항목을 바로 배정한다.

강의별로 작업 범위를 나누고 공용 manifest·큐·공개 저장소 반영은 조정자 한 명이 담당한다. 큐 선점은 최신 HEAD와 expected SHA로 기록한다. 이전 실행이 진행 중이면 같은 항목을 다시 선점하지 않는다. 임대는 120분이며 실제 실행 상태·체크포인트를 확인한 뒤 재개한다.

## 한 번의 실행 순서

1. 최신 큐와 스크립트 바인딩을 읽고 기존 제80회 원고의 해당 구간을 연다. 같은 입력 지문으로 완료한 검토는 반복하지 않는다.
2. **확인된 스크립트 불일치 수정과 제작 대기 항목을 먼저 처리**한다. 그다음 남은 강의의 스크립트와 기존 도식을 대조한다. 도식의 범위는 해당 스크립트에 설명된 학습 목적 안으로 한정한다.
3. 조건·예외·핵심 표현을 유지한 채 표·비교·순서·그룹으로 시각화한다. 같은 학습 목적의 기존 도식이 있으면 필요한 부분만 수정한다.
4. 실제 빠진 비교·절차·숫자가 있으면 `production_jobs`에 구체적 원고 구간·목적·조건을 남기고 제작한다. 스크립트에 없는 예시·확장 법리·새 주제를 임의로 추가하지 않는다.
5. 렌더링과 아래 검수를 마친 뒤 해당 강의 폴더에 반영한다. 구조화 도식 원본·manifest·README·파일 해시·검수 기록·큐 상태를 함께 갱신한다.
6. 최신 HEAD에 대한 expected SHA로 커밋한다. 다른 작업이 먼저 반영됐으면 새 HEAD를 읽어 변경 파일만 다시 적용한다. 강제 덮어쓰기를 하지 않는다.
7. 종료 전 실제 완료·보강 필요·차단 사유·재개 지점을 저장하고 임대를 해제한다. 공개 파일과 큐를 다시 확인하고 결과를 보고한다.

## 스크립트 매핑

DR-045의 `본훈_2-2의2.txt`, DR-047의 `본훈_2-3의3.txt`, DR-078의 `본훈_2-65.txt`는 기존 경로 키다. 파일명을 바꾸거나 없는 조문을 만들지 않는다. 카탈로그의 실제 조문과 원고 본문을 사용한다. 매핑의 `resolved_article`과 `article_key`를 참조한다.

제80회 기존 설정의 법령 기준일은 **2027-02-02**다. 이 값은 기존 사용자 지정 적용 기준일이며 시험일 필드와 구분한다. DR-060의 2027-01-01 시행 부분은 스크립트의 제80회 적용 내용으로 설명한다.

## 디자인과 검수

- 기준 디자인: `integrated-defense/lesson-005/diagrams/style-studies-v2/07-notion-editorial.svg`.
- 1600×1120, 밝은 종이 배경·진한 글자·얇은 선·왼쪽 괄호·오른쪽 타원 강조를 유지한다.
- 정확한 텍스트를 벡터/코드로 제작하고 SVG·PNG·무손실 WebP를 내보낸다.
- 스크립트의 숫자·기산점·주체·조건·예외·시험 핵심 표현과 일치하는지 먼저 확인한다. 단어를 임의로 바꿔 정답 근거를 흐리지 않는다.
- 원고와 공식 인용 사이에 명백한 충돌을 발견하면 해당 강의·구절만 기록하고 확인한다. 전체 원고 재작성이나 별도 법령 전수조사로 확대하지 않는다.
- 실제 이미지를 열어 문자 누락·겹침·잘림·어절 줄바꿈을 확인한다. PNG와 무손실 WebP의 해상도·픽셀 및 파일 해시를 확인한다.
- 강의 폴더의 실제 최대 도식 번호 다음을 새 ID로 사용한다. 기존 ID를 다른 학습 목적에 재사용하지 않는다.
- 공개 저장소에는 도식과 출처 식별 정보만 담고 비공개 강의 스크립트 전체를 복제하지 않는다.
- 재생성은 현재 `diagrams.source.json`과 `script-basis.json`을 사용한다. 최초 제작용 법령 추출 중간 파일로 검수된 원본을 덮어쓰지 않는다.

## 상태와 중복 방지

검토는 `queued → running → completed`, 제작은 `queued → running → qa → completed`다. 접근 실패는 `blocked`로 구분한다. 부분 대조와 전체 강의 검토 완료를 구분하고 완료 근거에 원고 구간과 해시를 남긴다.

중복 키는 **강의 ID + 스크립트 해시 + 원고 구간 + 학습 목적 + 디자인 버전**이다. 큐가 끝나면 제80회 기존 스크립트·매핑·도식의 변경 지문만 확인한다. 변경이 없으면 기존 도식을 반복 생성하지 않는다.

## 보고

신규·수정 도식 수, 전체 스크립트 대조를 완료한 강의 수, 남은 검토·제작 큐 수, 구체적 차단 사유, 실제 반영 커밋과 대표 링크를 간결하게 보고한다. 원고 바인딩 검증과 도식 내용 대조를 다른 실적으로 센다.

이 지침을 읽는 예약은 1시간 간격으로 운영하며, 실행 주기는 연결된 자동화 서비스에서 관리한다.
