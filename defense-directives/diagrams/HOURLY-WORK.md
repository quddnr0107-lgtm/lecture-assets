# 훈령 도식: 매시간 큐 실행 지침

[작업 큐](production-queue.json) · [전체 78강](../README.md) · [도식 목록](../diagrams-manifest.json) · [제작 원본](diagrams.source.json)

## 시작 기준

훈령 DR-001~DR-078의 **78강·190장, SVG/PNG/WebP 570개 파일은 제작 완료** 상태다. 기준 커밋은 `03c609868e7d02dd5a2e94dac760f6d2593a43c2`다. 새 큐의 78건은 각 강의의 **원고 대비 도식 보강 필요성 검토**이며, 78장의 미제작 도식을 뜻하지 않는다. 추가 장수 목표를 임의로 정하지 않는다.

큐 전체를 열어 두고 매 실행에서 사용할 수 있는 동시 작업 수를 최대로 쓴다. 설정 당시 환경은 총 4슬롯으로, 조정자 1명과 작업자 3명을 사용한다. 이후 환경의 실제 한도가 달라지면 그 한도에 맞춘다. 처리 가능한 작업이 남아 있고 실행 자원이 허용하면 완료된 작업자에게 다음 항목을 바로 배정한다.

## 매 실행 순서

1. 최신 기본 브랜치의 큐·도식 목록·원본·검수 기록을 읽는다. 실제 강의 원고와 적용 회차·기준일, 공식 원문의 버전·조문별 시행일을 확인한다. 기존 검수는 재사용하고 변경 지문과 미완료 큐부터 처리한다.
2. 이전 실행이 진행 중이면 같은 항목을 다시 선점하지 않는다. 조정자는 최신 HEAD에 대한 expected SHA를 확인해 실행 ID와 선점 항목을 저장한 뒤 작업을 배정한다. 실행 임대는 120분이며, 만료만으로 재개하지 말고 실제 실행 활동·체크포인트를 확인한다.
3. 먼저 DR-060의 시행일 구분, DR-013·024·062·009·067의 복잡한 요건·절차·수치 비교를 확인한다. DR-045·047·078은 이미 바로잡은 조문 연결을 유지하면서 실제 원고의 남은 설명을 대조한다. 우선순위는 부족하다는 판정이 아니며 최신 근거로 바꿀 수 있다.
4. 강의별 학습 목적과 기존 도식을 대조한다. 누락된 요건 비교·예외·시간 순서·주체별 절차가 실제로 있을 때만 구체적 보강 작업을 `production_jobs`에 만든다. 검토가 끝나도 보강이 필요하지 않을 수 있다.
5. 작업자에게 서로 다른 강의 또는 충돌하지 않는 산출물을 맡긴다. 공개 저장소 반영과 공용 manifest·queue 갱신은 조정자 한 명이 담당한다.
6. 필요한 도식을 제작하고 아래 검수를 통과한 뒤 공개 저장소의 해당 과목·강의 폴더에 반영한다. 강의 원고·음성·영상·사이트 배포까지 완료했다고 확대 보고하지 않는다.
7. 실행 종료 전에 완료·보강 필요·차단 사유·다음 항목을 기록한다. 진행 중 작업은 재개 지점을 남기고 임대를 해제한다. 큐 상태와 실제 공개 파일을 대조한 뒤 결과를 한국어로 보고한다.

## 제작과 검수

- 기준 디자인: `integrated-defense/lesson-005/diagrams/style-studies-v2/07-notion-editorial.svg`. 1600×1120, 밝은 종이 배경, 진한 글자, 얇은 선, 왼쪽 괄호와 오른쪽 타원 강조를 유지한다.
- 기존 도식과 같은 학습 목적·조문 범위이면 새 장수를 늘리지 않는다. 필요하면 기존 장의 근거 있는 수정으로 처리한다.
- 수치·기간·권한 주체·요건·예외·조문 번호와 버전·시행일을 공식 원문과 대조한다. 적용 회차의 기준일과 현재 시행 여부를 구분한다. DR-060 관련 제3216호 제16조제4항제4호의 2027-01-01 시행 예외를 유지한다.
- SVG를 편집 가능한 원본으로 만들고 PNG 및 무손실 WebP를 내보낸다. 글자 누락·깨짐·겹침·영역 이탈·줄바꿈을 확인하고 실제 이미지를 눈으로 검수한다. 정확한 법령 도식은 결정적인 벡터/코드 렌더링을 사용한다.
- 새 도식 ID는 강의 폴더의 실제 최대 번호 다음으로 부여한다. 기존 ID를 다른 주제에 재사용하지 않는다.
- `diagrams.source.json`, `diagrams-manifest.json`, 강의별 README, 검수 기록과 파일 해시를 실제 산출물에 맞게 갱신한다. 공개 결과에는 도식에 필요한 내용과 근거를 담는다.
- renderer와 packager를 실행하기 전에 현재 스크립트의 입력과 출력 범위를 확인한다. 전체 재생성이 필요하지 않으면 변경 대상만 처리한다.

## 상태·중복·재개 규칙

검토 항목은 `queued → running → completed`로 전이한다. 접근 실패는 `blocked`로 기록하며 성공이나 변경 없음으로 처리하지 않는다. 완료 결과에는 검토한 입력 지문, 근거, 보강 필요 여부와 생성한 작업 ID를 남긴다.

제작 항목은 `queued → running → qa → completed`로 전이한다. 최소 필드는 ID, 강의 ID, 학습 목적, 조문 범위, 공식 근거 버전/해시, 디자인 버전, 중복 판정 키, 상태, 담당 실행, 출력 경로, 검수 결과와 반영 커밋이다.

중복 판정 키는 **강의 ID + 근거 버전/해시 + 조문 범위 + 학습 목적 + 디자인 버전**으로 만든다. 완료된 검토의 입력 지문이 같으면 다음 실행에서 반복 검토하지 않는다. 입력이 달라지면 바뀐 범위만 다시 큐에 넣는다.

공개 반영은 최신 HEAD를 기준으로 한 단일 작성자가 수행한다. expected SHA가 달라지면 최신 변경을 읽고 변경 파일만 다시 적용한다. 강제 덮어쓰기를 하지 않는다. 해당 실행에서 만든 커밋에 파일과 큐 상태가 실제로 있는지 다시 확인한다.

## 매 실행 보고

실제 신규 도식 수, 수정 도식 수, 완료한 강의 검토 수, 남은 검토·제작 큐 수, 차단 사유, 반영 커밋과 대표 파일 링크를 간결하게 적는다. 검토 완료와 신규 제작을 별도로 센다. 모든 검토가 끝나고 변경이 없으면 “새 작업 없음”으로 보고하고 같은 190장을 반복 생성하지 않는다.

이 문서와 JSON은 예약 실행이 읽는 운영 기준이다. 예약 자체는 연결된 자동화 서비스에 등록되어야 실행된다.
