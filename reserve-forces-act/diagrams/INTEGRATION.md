# 예비군법 도식의 강의 제작 연결 안내

## 현재 상태와 기준 버전

이 묶음은 제80회 기존 예비군법 스크립트를 바탕으로 만든 **34강·335장의 SVG·PNG 자산**이다. 강의 ID, 제목, 원고 연결 및 도식 목록을 확인했으며, **학습 사이트나 동영상에 도식을 삽입하는 연결은 아직 완료하지 않았다.**

이 문서의 자산 기준 커밋은 `779649a9e54b399bb7596d1782e538486872102c`이다. 아래 경로·해시·도식 번호는 이 버전을 기준으로 설명한다. 제작 작업을 시작할 때는 manifest와 이미지가 같은 자산 커밋에 속하도록 고정한다.

- 자산 저장소: `quddnr0107-lgtm/lecture-assets`
- 자산 목록: [manifest.json](manifest.json)
- 원고 연결: [source-index.json](source-index.json)
- 내용 검수 범위: [review/CONTENT-REVIEW.md](review/CONTENT-REVIEW.md)
- 기존 강의 코드 검토 기준: `quddnr0107-lgtm/yebijun-muhanhoidok234`의 `352b4eb71cced810612b05c9a531060e1470d1f5`

출처 원고와의 연결은 식별자·경로·커밋·해시·줄번호로 유지한다.

## 1. 현재 소비 코드가 요구하는 형식

다음은 위 강의 코드 기준 커밋에서 확인한 동작이다. 경로와 위치는 연결 작업자가 원래 저장소에서 확인할 수 있도록 기록했다.

| 소비 경로 | 현재 요구하는 입력과 동작 | 새 도식과 연결할 부분 |
| --- | --- | --- |
| `_deploy/integrated-lectures.js` 266행, `_deploy/lecture-landscape.js` 63~72행 | 강의 ID와 기존 강의 버전으로 영상 세션을 열고, 해당 강의의 MP4를 재생한다. | 새 manifest를 읽는 경로가 아니다. 도식 파일을 추가하는 것만으로 기존 영상의 화면은 바뀌지 않는다. |
| `_deploy/lecture-video-server.mjs` 1·86·92~93행 | 영상 inventory의 릴리스 경로·파일 크기·영상 SHA와 맞는 MP4를 제공한다. | 도식을 포함한 완성 영상을 제작하는 경우, 영상 자산과 그 inventory를 연결하는 별도 작업이 필요하다. |
| `src/video-lecture-focus/storyboard.js` 5~16행 | 기존 장면 연결은 원고에서 정확히 한 번 나타나고 순서가 증가하는 앵커를 요구한다. | `sourceRanges`를 앵커나 재생 시각으로 그대로 넣을 수 없다. 원고의 표시 위치를 확인한 별도 연결이 필요하다. |
| `src/video-lecture-focus/runtime.js` 68~75행 | 등록된 사진 ID를 선택한 뒤 `/tb-photo-v1/{id}.webp` 형식의 경로를 만든다. | 도식의 PNG·SVG 경로를 기존 사진 ID 자리에 넣으면 이 형식과 맞지 않는다. 실제 파일 경로를 읽는 도식용 입력 처리가 필요하다. |
| `scripts/build-video-lectures.mjs` 11~29행 | 사진 목록, 행동 storyboard, 원고 연결, 사진 이벤트를 빌드 입력으로 사용한다. | 이 자산의 `manifest.json`은 해당 입력 목록에 연결되어 있지 않다. |

기존 예비군 행동 storyboard는 498개 구간이고 새 도식은 335장이다. 두 배열의 같은 인덱스를 서로 연결하는 방식은 사용할 수 없다. 실제 강의 제작에서 어떤 구간에 어느 도식을 표시할지 별도로 정해야 한다.

## 2. 식별자와 순서 읽기

| 필요한 정보 | manifest에서 읽을 위치 | 사용 방법 |
| --- | --- | --- |
| 강의 ID | `lessons[].lessonId` | `RL-001`부터 `RL-034`까지 사용한다. 기존 강의 카탈로그의 `id`와 연결하며, 대문자와 세 자리 번호를 유지한다. |
| 도식 ID | `lessons[].diagrams[].id` | 예: `purpose-four-actions`. 연결 파일에서 `diagramId`라고 부른다면 이 값을 사용한다. 현재 manifest의 실제 필드명은 `id`다. |
| 자산 식별 키 | 강의 ID와 도식 ID의 조합 | `RL-001`과 `purpose-four-actions`처럼 함께 보관한다. 파일명의 순번을 도식 ID 대신 사용하지 않는다. |
| 목록 순서 | `lessons` 및 각 강의의 `diagrams` 배열 순서 | 도식 목록·갤러리·수동 편집 자료에서는 이 순서를 유지한다. 필요하면 배열 위치에 1을 더해 도식 번호로 내보낸다. 현재 manifest에 별도 `diagramOrder` 필드는 없다. |
| 화면 표시 순서 | 별도 표시 큐 | 원고·음성에 맞춘 표시 순서다. 목록 순서와 구분하고, 같은 도식 ID의 재표시를 허용한다. |

34개 강의의 ID·순서·제목은 검토 기준의 기존 강의 카탈로그와 일치한다. 현재 335개 도식 ID에도 중복이 없다. 단순 연결을 위해 강의 번호를 새로 매기거나 제목으로 추측해서 매칭할 필요가 없다.

## 3. 파일 경로와 자산 버전 고정

`svg`, `png`, `contentPath`는 모두 **자산 저장소 루트 기준의 상대 경로**다. manifest가 있는 `reserve-forces-act/diagrams/`를 기준으로 한 상대 경로가 아니다.

첫 도식의 SVG 경로는 다음과 같다.

```text
reserve-forces-act/lesson-001/diagrams/rl-001-01-purpose-four-actions.svg
```

확정 자산 커밋을 사용한 [첫 도식 SVG의 고정 주소](https://raw.githubusercontent.com/quddnr0107-lgtm/lecture-assets/779649a9e54b399bb7596d1782e538486872102c/reserve-forces-act/lesson-001/diagrams/rl-001-01-purpose-four-actions.svg):

```text
https://raw.githubusercontent.com/quddnr0107-lgtm/lecture-assets/779649a9e54b399bb7596d1782e538486872102c/reserve-forces-act/lesson-001/diagrams/rl-001-01-purpose-four-actions.svg
```

다른 파일도 같은 저장소·커밋의 루트에 manifest의 경로를 붙인다. manifest 파일 주소를 기준으로 경로를 해석하면 `reserve-forces-act/diagrams/` 아래에 잘못 연결될 수 있다. 저장소를 내려받아 사용하는 경우에는 체크아웃 루트에서 경로를 해석한다.

현재 갤러리는 이 경로를 자체적으로 변환해 사용한다. 외부 제작 도구가 갤러리의 URL 변환을 자동으로 공유하는 것은 아니다. 근거는 `tools/render_reserve_diagrams.py` 215~223행이다.

자산 커밋은 manifest에 들어 있는 원고의 `sourceCommit`과 다르다. 제작용 연결 파일에는 자산 커밋을 별도 메타데이터로 보관하고, 해당 버전의 manifest와 파일 해시를 함께 사용한다. `main`이 나중에 바뀌더라도 기존 제작 결과를 재현할 수 있도록 하기 위해서다.

## 4. 출처와 해시 사용법

| 필드 | 뜻과 확인 대상 |
| --- | --- |
| `source.sourceRepository` | 원고가 있는 저장소다. 자산 저장소와 구분한다. |
| `source.sourcePath` | 원고 저장소 루트에서의 TXT 경로다. 공개 자산 경로로 해석하지 않는다. |
| `source.sourceCommit` | 도식의 근거로 삼은 원고 버전이다. 이 묶음의 34강은 `352b4eb71cced810612b05c9a531060e1470d1f5`를 기준으로 한다. |
| `source.gitBlobSha` | 해당 원고 파일의 Git blob 식별자다. `sourceSha256`과 다른 종류의 값이다. |
| `source.sourceSha256` | 원고 파일 바이트의 SHA-256이다. 원고를 대조하는 작업자는 지정한 버전의 원고와 일치하는지 확인한다. |
| `contentSha256` | `contentPath`에 있는 도식 콘텐츠 JSON 파일의 SHA-256이다. 이미지 파일의 해시가 아니다. |
| `diagrams[].svgSha256` | 해당 SVG 파일 바이트의 SHA-256이다. |
| `diagrams[].pngSha256` | 해당 PNG 파일 바이트의 SHA-256이다. |
| `diagrams[].sourceRanges` | 도식의 명제를 뒷받침하는 원고 줄번호와 주제의 목록이다. 줄번호는 1부터 시작하며, 시작·끝 줄을 포함한다. |

다운로드한 파일은 줄바꿈·공백 등을 변환하기 전의 바이트로 해당 해시를 비교한다. 원고 전체가 없는 공개 자산 이용자는 이미지·콘텐츠 해시를 확인할 수 있고, 원고 대조는 해당 원고에 접근할 수 있는 제작 작업자가 수행한다.

**기존 카탈로그의 음성·강의 버전을 도식 해시로 대체하지 않는다.** `scripts/build-integrated-catalog.mjs` 27행에서 카탈로그의 `version`은 강의 릴리스 인덱스 해시로 정해진다. `contentSha256`, `svgSha256`, `pngSha256` 또는 `sourceSha256`을 그 자리에 넣는 것은 같은 의미의 갱신이 아니다.

## 5. 근거 범위와 재생 큐를 구분하기

**`sourceRanges`는 자동 자막이나 음원의 타임코드가 아니다.** 원고의 줄번호를 초 단위로 비례 환산하거나, 각 도식의 가장 이른 근거 줄에서 반드시 한 번만 표시하는 방식으로 사용하지 않는다. 하나의 도식이 앞뒤에 떨어진 설명을 함께 정리할 수 있고, 공통 조문 도입 줄이나 비교 근거를 참조할 수도 있다.

기존 원고와 나레이션 순서를 따라 편집할 때는 아래처럼 같은 도식을 다시 보여 줄 수 있어야 한다. 다음 표는 각 강의의 일부 구간에 대한 표시 순서이며, 확정된 재생 시각을 뜻하지 않는다.

| 강의 | 원고의 구간 순서 | 도식 표시 순서와 ID |
| --- | --- | --- |
| RL-002 | 111~129행 → 131~137행 → 139~147행 | **04 → 05 → 04**. `guard-civil-support` → `weapon-mission-link` → `guard-civil-support` |
| RL-003 | 173행 → 175~187행 → 189~201행 → 203~219행 | **08 → 09 → 10 → 08**. `volunteer-period` → `volunteer-early-end` → `volunteer-leader-exception` → `volunteer-period` |
| RL-030 | 79~85행 → 87~91행 → 93~107행 | **04 → 05 → 04**. `commission-members` → `team-leaders` → `commission-members` |

RL-002의 04번은 경비와 민방위 지원을 한 장에 묶었고, RL-003의 08번은 지원 기간과 뒤의 기산·연장 절차를 함께 담았다. RL-030의 04번은 위촉과 협의를 함께 정리했다. 이는 파일 순서가 뒤바뀐 오류가 아니라 같은 주제로 되돌아가는 원고를 영상에 연결할 때 처리할 부분이다.

특히 RL-003의 10번이 함께 인용하는 173행, RL-030의 04·05번이 함께 인용하는 57행은 비교 근거 또는 조문 도입이다. 이를 각 화면의 시작 위치로 기계적으로 취급하지 않는다. 표시 큐를 만들기 위해 기존 도식 배열을 근거 줄번호로 다시 정렬할 필요도 없다.

재표시는 같은 강의 ID·도식 ID를 다시 참조하면 된다. 이미지 파일을 복제하거나 새 도식 번호를 만드는 것은 필수가 아니다. 원고 기준 위치를 실제 재생 시각에 연결할 때는 검증된 녹음 구간을 사용한다. 기존 코드의 관련 확인은 `src/video-lecture-focus/photo-events.js` 31~38·61~70·103~122행, 작성 원칙은 `docs/VIDEO_LECTURE_ACTIONS.md` 38~45행에 있다.

## 6. 최소 연결 절차

1. **자산 버전을 고정한다.** 같은 자산 커밋의 manifest와 이미지를 사용하고, 실제 읽은 SVG·PNG의 SHA-256을 manifest와 대조한다.
2. **강의와 도식을 식별한다.** 기존 카탈로그의 강의 ID를 `lessonId`에 연결한다. 도식은 강의 ID와 `diagrams[].id`의 조합으로 선택하고, 수동 편집 목록에는 manifest 배열 순서와 정확한 파일 경로를 전달한다.
3. **실제 소비 경로를 정한다.** 영상 편집 도구에서는 PNG·SVG를 직접 사용한다. 기존 사진 장면 렌더러에 넣는다면 등록 사진 ID와 WebP 경로를 가정하는 부분에 도식용 처리를 추가해야 한다. 완성 MP4에 넣는 방식이라면 도식을 포함한 영상을 제작하고 그 영상의 릴리스·크기·SHA를 기존 영상 제공 경로와 연결하는 작업이 뒤따른다.
4. **동기화가 필요한 경우 표시 큐를 별도로 작성한다.** 원고 버전을 확인하고, 도식 ID에 원고 표시 위치와 검증된 녹음 구간을 연결한다. 한 도식에 여러 표시 구간을 허용한다. 실제 녹음 경계를 확인하지 못한 상태에서는 목록 순서만 제공하고 재생 타이밍 연결 완료로 표시하지 않는다.
5. **연결한 경로에서 필요한 부분을 확인한다.** 선택한 강의의 실제 파일 표시, SHA 일치, 위 세 재표시 사례, 기존 카탈로그의 음성 버전 유지 여부를 확인한다. 사이트나 영상이 새 도식을 실제로 소비하는 것이 확인된 뒤에 그 연결 상태를 별도로 기록한다.

이 문서는 연결 규약과 확인된 미연결 부분을 인계한다. 원고·음원·강의 카탈로그·사이트의 변경이나 배포를 수행한 기록은 아니다.
