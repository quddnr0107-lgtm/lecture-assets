# 통합방위법 도식 큐 실행 기준

## 최우선 내용 기준

사용자 정정: **제80회(27년 전반기), 기존 강의 스크립트로 제작한다.**

[기준 원고 목록·버전](EXAM80-SCRIPT-SOURCE.json)의 통합방위법 25편이 내용 기준이다. 실제 강의 번호 TB-001~025를 사용하며 TB-010은 제9조의2다. 각 원고의 해시를 확인하고 제목·설명 순서·기관명·숫자·주체·요건·예외를 그대로 따른다. 도식의 요약과 시각 배치는 바꿀 수 있으나 원고를 새로 쓰거나 원고 밖 내용을 추가하지 않는다.

현재 법령·검색 결과를 이유로 기존 원고를 임의로 갱신하지 않는다. 제79회 자료를 섞지 않는다. 원고와 다른 부분은 해당 항목만 확인 필요로 기록한다. 근거 URL과 시행일은 출처 메타데이터로 보존하되 이를 개정 설명의 추가 지시로 취급하지 않는다.

## 재사용과 완료 기준

기존 49개와 후속 6개를 포함한 55개 도식은 [원고 일치 검수](../notion-v1/script-alignment.json)를 먼저 확인한다. 이 검수는 원고와 도식 텍스트의 비교이며 이미지 재검수나 전체 큐 완료를 뜻하지 않는다. 내용 수정 시 도식 해시와 원고 근거를 함께 갱신한다.

신규 도식과 모바일 변형, 검수 작업은 따로 센다. 원고가 뒷받침하지 않는 새 설명으로 수량을 늘리지 않는다. 현재 30개 작업의 완료 상태는 queue.json을 따른다.

## 작업 배정

1. 매 실행 최신 main의 이 문서·queue.json·기준 원고 목록·content·manifest·style-guide를 읽는다.
2. 의존성이 완료된 작업을 우선순위대로 선택하고 실제 가용 동시 슬롯을 최대로 쓴다. 최초 확인 한도는 조정 1 + 제작 3, 총 4슬롯이다. 완료 즉시 다음 작업을 배정한다.
3. 작업 전에 실행 ID·시작·만료 시각의 lease를 기록한다. 다른 실행의 유효한 작업을 중복 처리하지 않는다. 이전 실행이 종료됐거나 lease가 만료되면 실제 산출물을 먼저 확인하고 복구한다.
4. 작업자는 강의별 파일을 분담하고 조정 담당이 공용 content·manifest·gallery·queue를 취합한다. 한 작업이 막히면 다른 독립 작업을 계속한다.

## 제작과 검증

- 선택한 7번 흑백 편집형과 기존 SVG 제작 코드를 사용한다. 강의 스크립트 내용은 재작성하지 않는다.
- 모든 보완 도식은 해당 제80회 원고와 대응한다. 기존 원고에 없는 개정 날짜·기관 설명을 기억할 문장에 새로 넣지 않는다.
- 모바일은 폭 1080px, 390px 표시에서 핵심 본문 14px 이상을 기준으로 실제 한 열 재배치를 한다. 필요한 페이지로 나누고 의미 단위 줄바꿈을 한다.
- 주체·요건·의무·재량·예외를 보존한다. 구성 비교를 절차 화살표로 바꾸지 않는다.
- SVG·PNG·WebP의 한글·잘림·겹침·화살표·작은 화면 가독성을 이미지로 확인한다. 원고 의미 일치, 출력 텍스트, 크기·SHA-256·강의별 링크를 확인한다.
- 모바일은 원본 ID와 페이지를 연결하고 별도 manifest에 기록한다. 새로운 법 내용 도식으로 중복 집계하지 않는다.
- 비공개 원고 전문·짧은 앵커·영상·음성·서명 URL·비밀값을 공개 저장소에 넣지 않는다. 공개 자료에는 도식·법령 요약·강의 ID·검수와 해시를 저장한다.

## 저장소 반영과 보고

공개 lecture-assets의 과목·강의별 폴더에 저장한다. 커밋 직전 최신 HEAD와 트리를 읽고 다른 과목·사진 파일을 보존한다. expected SHA가 바뀌면 다시 읽어 병합하며 강제 갱신하지 않는다.

실제 결과 파일·원고 일치 검수·이미지 검수·manifest가 저장되고 원격까지 확인된 경우만 done으로 기록한다. runs/에 작업 ID·검수·파일·커밋을 남긴다. 단순 조회나 큐 등록을 제작 완료로 세지 않는다.

범위는 통합방위법 도식 자산이다. 매 실행 실제 완료 작업·도식 수·모바일 강의 수·누계·남은 수·저장소 링크·실제 막힘을 간결히 보고한다. 모든 작업 검증 후 최종 묶음을 갱신하고 이 전용 예약만 종료한다.
